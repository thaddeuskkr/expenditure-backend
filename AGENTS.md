# Working on Expenditure

## Scope and conventions

- Read the files involved before editing. Preserve unrelated work in the checkout.
- Keep public READMEs short: an introduction, local setup, and essential installation steps. Put maintenance guidance here.
- This file is tracked too. Never put credentials, tokens, account data, or private deployment details in documentation. Documentation placement is not an access control.
- No demo mode, fake workspace data, authentication bypasses, or legacy API aliases in product code. Do not add backward compatibility unless explicitly requested.
- Do not commit screenshots, deployment archives, downloaded binaries, runtime databases, `.env.local`, or build output. Use temporary directories for verification artifacts.

## Where changes belong

- `pocketbase/pb_hooks/main.pb.js`: authenticated version check, overview and native personal transaction provenance.
- `pocketbase/pb_hooks/configuration.pb.js`, `configuration.js`: account initialization, category management/order, preferences, and native record validation.
- `pocketbase/pb_hooks/circles.pb.js`, `circles-service.js`: Circle routes, permissions, transactions, and ledger operations.
- `pocketbase/pb_hooks/circle-categories.js`, `circle-categories.pb.js`: owner/Admin Circle category creation, rename/archive/restore, ordering and replacement from the acting manager’s personal settings. Unmatched categories used in history remain archived.
- `pocketbase/pb_hooks/expense-moves.js`, `expense-moves.pb.js`: atomic personal/Circle transfers, independently authorized return moves, recurring schedule transfer, and personal-to-Circle retry markers.
- `pocketbase/pb_hooks/receipt-core.cjs`, `receipt-core.d.cts`: shared receipt math and types. Receipt expenses retain items, assignments and charge settings in `receipt`, with server-verified exact shares. Discounts precede charges; added GST includes service charge; included GST is extracted before calculating added service and GST on that service. Allocate charges with deterministic integer rounding.
- `pocketbase/pb_hooks/circles-core.cjs`: allocation and settlement calculations used for server-side allocations. Keep `circles-core.d.cts` in sync.
- `pocketbase/pb_hooks/exchange-rates.js`, `overview.js`, `request.js`: cached rates, complete-dataset reports, and timestamp validation.
- `pocketbase/pb_hooks/recurrence.js`, `recurrence.pb.js`: recurring schedules, timezone/calendar advancement, transactional generation and pause errors. Schedules live on the original transaction; generated entries have no recurrence and zero interval/day/month fields and empty weekdays.
- `pocketbase/pb_hooks/transactions.js`, `transactions.pb.js`: preference-aware, session-only combined transaction feed. Filter and paginate both ledgers together on the backend; return positive allocated Circle shares with original records and Circle labels.
- `pocketbase/pb_hooks/currencies.json`: shared currency catalog; use its precision on both sides.
- `pocketbase/pb_hooks/timezones.json`: shared timezone catalog for the preferences schema and iOS selector. Save the timezone ID; derive displayed GMT offsets for the current date so daylight-saving changes remain correct.
- `pocketbase/pb_migrations/`: ordered schema/data migrations. `tests/`: domain tests and disposable PocketBase integration/upgrade tests.

## Data and API rules

- Use the database field names and types directly in requests, responses, and iOS models. Update callers and tests together when changing a contract.
- Monetary fields are `amount`: integer currency minor units, never floating-point money. SGD 6.50 = 650; JPY 650 = 650; KWD 1.234 = 1234. The current maximum is enforced in the schema/core. Use `payment_method` for payment labels.
- `kind` distinguishes `expense` and `income`; both store positive `amount`. Income never consumes spending budgets. Circle income reverses the expense balance deltas: `paid_by` identifies the recipient who owes the allocated shares.
- Recurrence supports expenses and income in both ledgers. `recurrence_interval` selects every 1–365 days/weeks/months/years (0 is stored when disabled); `recurrence_weekdays` contains ISO weekdays (Monday=1, Sunday=7); empty uses the original weekday. Weeks start Monday and every-N-week schedules stay anchored to the entry week. `recurrence_month` chooses a yearly month (1–12; 0 uses the entry month). `recurrence_day` applies to monthly/yearly schedules: 0 keeps the original date, -1 means last day, and 1–31 chooses a date clamped in shorter months. Explicit weekdays and monthly/yearly dates can recur later in the entry week/month/year; intervals remain anchored to that period. Use the saved schedule timezone, including downtime catch-up. Preserve transactional generation/cursor advancement, original month-end anchors, author/membership checks and visible pause errors. Editing a schedule affects future entries; stopping/deleting it preserves generated history.
- Circle shares use `member` (membership ID). Even inputs contain only `member`; exact inputs add integer `amount`; percentage inputs add integer `percentage_bp` (6000 = 60%). Saved shares contain the calculated `amount`. Preserve deterministic largest-remainder rounding.
- Circle `owner` is a user ID. `paid_by`, share members, settlement participants, and `created_by` are membership IDs. Never interchange the two kinds of IDs.
- Relations retain their stored IDs. Public related data goes under `expand.user` or `expand.circle`; do not replace relation IDs with objects. Keep profile projections limited to public fields.
- `exchange_rates.quotes` and `dates` have the same structure in storage and responses. Preferences and default categories are persisted during initialization; do not synthesize legacy settings on reads.
- Validate input on the server even when a iOS form already validates it. Preserve ownership checks, hidden secrets, and server-managed provenance. Never expose superuser credentials to the app or Shortcuts.
- Circle membership stores `is_admin`, `can_add`, `edit_scope` and `delete_scope` (`none`/`own`/`all`), plus independent `move_scope` (`none`/`payer`/`all`) with a `version` for permission changes. Own means the entry's `created_by`, not `paid_by`. New members default to Admin disabled, Add allowed, Edit own, Delete own and Move when payer; rejoining retains their saved permissions. The owner and Admins can update active members’ permissions, including granting/revoking Admin. The owner’s membership and permissions remain protected. Admin overrides transaction restrictions and grants settings, category, invitation, membership and repayment management. Only the owner can transfer ownership or delete the Circle. `circle.can_manage` is the current member’s effective owner/Admin access; `is_owner` still means actual ownership. Apply these permissions to expenses and income, including Shortcuts, personal-to-Circle moves and future recurring generation; keep repayments independent. Denied recurring generation pauses with a visible error. Confirmed personal-to-Circle move retries can still replay after Add is revoked. Moving to personal uses only `move_scope`, independent of Add/Edit/Delete. `payer` requires the actor’s membership to match `paid_by`; `all` allows any Circle entry to move to the actor’s personal ledger. Owners and Admins have effective `move_scope=all`. Upgrades set Move to none when stored Edit was none, otherwise payer; preserve membership and ledger timestamps, balances and schedule cursors.
- Circle writes must check authorization and balances inside their transaction. Keep version checks for stale edits, verified-email invitation matching, and per-action permissions. Preserve former member IDs/history; historical changes must not alter their balances. Settlements cannot overpay or mix currencies and never move money.
- Recorded repayments can be edited by their original author, the Circle owner or an Admin using their current version. Validate financial changes against current balances with the original repayment reversed, preserve the repayment ID/creator/created timestamp, and recalculate suggestions from the saved ledger. Notes/date-only edits must remain possible after later ledger changes without changing any balances.
- Deleting accounts marks retained memberships inactive; deleting an owner account cleans up owned circles. Do not derive substitute membership status on reads.
- Moved personal expenses retain `moved_to` and `moved_circle` as server-managed move markers for confirmed retries. Exclude them from every personal list, report, export, and currency query. Never clear these markers on Circle deletion or allow native clients to revive or edit receipts. Circle entries preserve their original ID, money, timestamps and provenance; they initially assign 100% to the moving membership.
- Circle expenses and income can move to the acting user’s personal ledger through the session-only move-to-personal route. Check active membership, independent Move scope and version inside the transaction. Payer scope compares `paid_by` with the actor’s membership; all scope does not require being the payer or author. Edit access alone never grants Move access. Move the full amount, map to an active personal category, preserve currency, timestamps, provenance and recurrence checkpoints, remove the Circle split, and protect former-member balances. Recorded repayments remain. No Circle-to-personal move receipts or source snapshots are retained. A repeated move returns 404 because the source is gone; refresh both ledgers and explain that an unconfirmed move may already have succeeded. Create a fresh personal ID so earlier personal-to-Circle receipts remain immutable.
- Personal expenses, budgets and Circle entries store category relation IDs. An empty budget category means the overall monthly budget. Session requests use IDs. Shortcuts resolves category names in the app. Related labels are exposed through `expand.category`; report buckets add `category_name`, and combined feeds add `budget_category_name`. Category renames update the category row only, preserving ledger IDs, timestamps, schedule cursors and Circle edit versions. Archiving/disabling preserves history. Ordering includes archived categories and checks `previous_ids` before saving; do not overwrite concurrent reorder changes.
- New personal expense/income forms use `preferences.default_entry_currency` (empty follows the main currency) and separate `default_expense_category` / `default_income_category` category relations (empty uses Other, then the first active category). Category defaults must belong to the user and be active; renames retain IDs, and archiving clears matching defaults atomically. Disabling the preferred currency resets it to follow the main currency. These defaults do not change edits, budgets, recurring generation, or Circle entries.
- Dates are stored as instants; the account timezone controls entry, report boundaries, daily grouping, and exports. Preserve the original instant when a minute-only picker is unchanged, including seconds and daylight-saving overlaps. Monthly report boundaries use the first valid local instant when midnight is skipped or repeated; entry pickers still reject nonexistent local times. Test daylight-saving boundaries. Defaults are SGD and Asia/Singapore.
- Persist `preferences.time_format` as `24h` (default) or `12h`. Apply it to all displayed times, date/time picker controls, recurring schedule timestamps and local export columns. Keep picker form values in 24-hour wall-clock notation, API/UTC timestamps in ISO format, and Excel dates typed; changing display format must not change instants or recurrence schedules.
- `preferences.show_circle_transactions` defaults to false and controls dashboard recent transactions, the Transactions page and its exports. Enabled lists include personal entries and positive own Circle expense/income allocations, including retained historical allocations for inactive memberships. Exclude settlements, zero/unallocated entries and moved receipts. Keep stored Circle `amount`/`category` intact; return `allocated_amount`, `budget_category` (personal ID) and `budget_category_name` separately. Circle actions must open Circle details rather than personal edit/delete routes. Budget totals do not depend on this display setting.
- Reports aggregate all matching records on the backend. Do not calculate monthly totals from paginated results.
- `preferences.include_circle_in_budgets` defaults to true for new and upgraded accounts and controls whether personal spending summaries and monthly budgets include positive allocated shares of Circle expenses, using the expense instant and the account's report boundaries. Count shares rather than payer totals, retain historical shares for inactive memberships, and exclude Circle income and repayments. Match Circle category names to personal categories by exact name, then unique case/whitespace-insensitive name; fall back to the personal Other category or the report's Other bucket. Do not create personal expense copies or change Circle categories/balances. Moved personal receipts remain excluded to prevent double counting.
- Exchange rates are reference estimates using the latest cached observations, including for historical expenses. Preserve original amounts, per-expense rounding, the shared refresh lease, failure throttling, stale/missing-rate warnings, and age limits. Never recompute Circle debts from exchange rates.

## Migrations and deployment

- Prepare installable PocketBase files for the user; do not assume server access. Copy all hook files, including JSON/CJS modules, together with all unapplied migrations. Keep the matching iOS app, schema and hooks coordinated.
- Add new migrations; do not rewrite applied history or remove old migrations because they contain earlier field names. Historical migrations are not runtime compatibility aliases. Back up before applying; some down migrations delete collections/data.
- Current backend status is version 46 in `main.pb.js`, checked by iOS startup and Shortcuts. When a contract changes, update both the reported and required version together.
- Circle detail accepts optional `expense_from`/`expense_to` (paired, inclusive/exclusive, at most 32 days), `expense_category` (Circle category ID or all), `expense_currency` (supported code or all), and `expense_search` (up to 200 characters; literal case-insensitive title/notes/payment-method search). Filters apply before expense pagination; balances, suggestions, totals and settlements remain all-time. Omitted filters preserve the complete ledger. Monthly/category/currency filtering was introduced in backend 31; search was introduced in backend 36.
- `preferences.payment_methods` is an ordered list of up to 50 unique, trimmed payment labels, each up to 80 characters. New and upgraded accounts start with an empty list. These are entry choices; renaming/removing a choice never rewrites stored `payment_method` labels, recurring seeds or Circle history. Ledger writes may retain labels outside the current list.
- Version 26 drops `circle_personal_moves` and its historical snapshots without changing live ledger entries. Recovering discarded receipts requires restoring a backup.
- The category-relation migration requires backup restoration to roll back; it removes duplicate retry fields after the existing retry migration has populated immutable receipts. User deletion removes personal expenses/budgets/preferences before categories inside one transaction.
- Test fresh installation and upgrades with existing records. Preserve IDs, amounts, timestamps, provider configuration, and ledger balances unless the requested change explicitly requires otherwise.
- PocketBase 0.40.6 is the validated server version; do not confuse it with the JS SDK version. Use Node 22.18 or later for the tests.

Keep the Swift catalog and validation in sync. Use theme variables for interface colours; category colours stay independent. Appearance drafts use the existing Save/Discard flow; preferences realtime/focus refresh shares saved changes across clients.

- Charcoal & Mauve is the default for startup, sign-in and native icons. Keep the native AccentColor/LaunchBackground assets coordinated. Green category seed colours are retired by backend 33 without resaving category rows or changing financial history; user-defined colours outside those exact retired values remain intact.


- Backend 35 removes the retired login-key collection and runtime routes. Keep the historical creation migration for already-applied history; the removal migration drops all stored credentials and metadata. - Backend 36 adds `shortcut` to personal and Circle transaction source choices without relabelling history. Session create requests use `X-Expenditure-Source: shortcut`; body fields cannot choose provenance and edits preserve it. Native Shortcuts output includes the saved `source`.

- Backend 38 adds locked `push_devices` and transactional `push_deliveries`. Session-only `/api/expenditure/push/devices/{installation}` registers/removes device tokens. Circle expense creation queues alerts only for other active members with registered devices; income, edits and replays do not notify. `push.pb.js` handles the outbox and minute cron; `push.js` rechecks membership/device ownership and retries delivery for 24 hours. `pocketbase/push-relay/` sends APNs over HTTP/2 with a server-only Apple signing key. Never put APNs/relay credentials in clients or tracked files.

- Backend 39 adds invitation and recorded-repayment notification types, optional source relations on `push_deliveries`, partial unique indexes per source, and per-device `circle_expenses`/`circle_invitations`/`repayments` choices. The authenticated device PATCH updates only owned registrations and cancels disabled queued types without needing an APNs token. Invitations require a case-insensitive matching verified email and remain pending/unexpired/unrevoked/unaccepted at delivery; no membership is required before joining. Repayments notify active participants other than the recorder; third-party Admin records notify both. Never notify unrelated members or imply that recording a repayment transfers money. Source creation/outbox stays transactional; edits do not enqueue, and financial repayment changes invalidate an older queued snapshot. Migration preserves existing device tokens, timestamps, financial history and pending expense deliveries; no historical events are backfilled.

- `pocketbase/push-relay/compose.yaml` runs the relay separately on the external `expenditure-push` network and publishes only a loopback host port. Docker builds use an explicit source allowlist; keys and shared secrets are mounted from host files. File-backed Compose secrets retain host permissions, so match the configured non-root UID/GID. The relay accepts either the shared secret environment variable or `EXPENDITURE_PUSH_RELAY_SECRET_FILE`, rejecting simultaneous sources. `/healthz` requires the same authentication as `/send` and verifies local readiness only, not Apple delivery. `tests/push-relay-startup.integration.mjs` checks real process startup from files, authenticated health, invalid configuration and graceful shutdown without contacting APNs. No backend schema/version change is needed for container packaging.

- Backend 40 adds opt-in per-device `shortcut_expenses` (default false), optional `push_deliveries.personal_expense` and personal expense create hooks. Automation alerts notify only the creator for personal and Circle expense creations. Circle members’ existing alerts remain independent. Income, edits, retries, ledger moves and recurring copies must not create own automation alerts. Server-generated copies carry hidden, unpersisted record metadata via `push.skipAutomation` to suppress only own automation alerts while preserving source and normal Circle alerts. Never export or store this marker. The iOS Notifications screen shares the settings draft Save/Discard flow; local defaults publish after acknowledged writes, failed saves preserve drafts, and its explicit local test checks permissions/sound without testing APNs delivery or applying drafts.

- Backend 41 adds session-only POST `/api/expenditure/push/devices/{installation}/test` for an immediate one-off APNs test. It validates token/environment/server/request ID, enforces existing registration ownership, uses only the authenticated recipient and a fixed message, and never changes device choices or the activity outbox. Tests work with all activity flags off. A per-account process-local cooldown/lease bounds requests; relay secrets and raw provider errors stay server-side. Response acceptance and client receipt are distinct. No schema migration is needed; rebuild the relay to accept `apns_test`.

- Backend 42 adds allowlisted `sort` on the session transaction feed and `expense_sort` on Circle detail: date_desc (default), date_asc, amount_desc, amount_asc. Filter and sort before pagination with deterministic date/created/ID ties. Amount sorting uses original currency units normalized to thousandths with integer arithmetic, never FX estimates or raw minor units. Transactions sorts personal amounts and allocated Circle shares; Circle ledgers sort full amounts. Counts, summaries and settlement paging stay independent. No schema migration is needed; install the new `ledger-sort.js` module with all hooks.

- Backend 43 adds `preferences.shortcut_payment_methods`, an account list of up to 100 explicit Shortcut names linked to existing payment choices. Match case and whitespace insensitively. New personal and Circle Shortcut creates resolve links inside their write transactions. Renaming or removing a payment choice alone preserves ledger history. A session-only preference save can opt in to updating matching personal Shortcut entries and Circle Shortcut entries authored by the active member when they have Edit access. Apply the preference and history writes atomically, preserve provenance and financial fields, exclude moved personal receipts, and increment updated Circle entry versions.

- Backend 44 adds the default-off `preferences.strip_wallet_merchant_location`. Only new session Shortcut writes marked with `X-Expenditure-Wallet-Tap: 1` use it. Review shows candidates and writes only explicitly selected original/replacement pairs, limited to editable personal and author-owned Circle Shortcut entries. Apply changes atomically, preserve financial data and check the current name under the writer lock.

- Backend 45 gives personal and Circle categories an immutable `kind` of expense or income. Names, order, active-category minimums and the 100-category limit apply within each list.
